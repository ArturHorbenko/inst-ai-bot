# Video retrieval with Atlas Vector Search

`video_retrieval_documents` holds one document for the whole Reel and one for
each timestamped retrieval chunk. Documents are generated by the dashboard's
`reel-retrieval/v1` enrichment job with prompt version `2026-08-07` and
embedded with Gemini. This is the active retrieval contract. Search and context
reads use exactly this contract by default, so results never mix document
versions. A caller may select another contract only by supplying both its trait
schema and prompt version explicitly.

## Configuration

Set these values in the **inst-ai-bot** environment:

```dotenv
GEMINI_API_KEY=...
ATLAS_VECTOR_INDEX=video_retrieval_vector
RETRIEVAL_EMBEDDING_MODEL=gemini-embedding-001
RETRIEVAL_EMBEDDING_DIMENSIONS=768
ATLAS_VECTOR_INDEX_TIMEOUT=300
ATLAS_VECTOR_INDEX_POLL_INTERVAL=5
```

The MongoDB deployment must be Atlas with Atlas Vector Search available. The
vector dimensions in the Atlas index must exactly match
`RETRIEVAL_EMBEDDING_DIMENSIONS`; changing either value requires rebuilding the
stored embeddings and index.

## Create the index

Run this from `inst-ai-bot` after loading its environment:

```bash
PYTHONPATH=. venv/bin/python scripts/setup_atlas_vector_index.py
```

The script creates the index when absent. When it already exists, it verifies
the vector dimensions, cosine similarity, and required version-filter fields,
then polls until Atlas reports it as `READY` and queryable. It fails with an
actionable error if the definition is incompatible, Atlas reports a failure, or
the bounded timeout expires. Alternatively create an Atlas Search index with
this definition:

```json
{
  "fields": [
    {
      "type": "vector",
      "path": "embedding",
      "numDimensions": 768,
      "similarity": "cosine"
    },
    {
      "type": "filter",
      "path": "trait_schema"
    },
    {
      "type": "filter",
      "path": "prompt_version"
    }
  ]
}
```

## MCP use

After the index reaches `READY`, agents use `search_videos(query)` to retrieve
video- or moment-level matches, then `get_video_context(content_hash, media_id)`
to inspect matching retrieval chunks and the original timestamped transcript.
Both default to `reel-retrieval/v1` / `2026-08-07`; pass both `trait_schema`
and `prompt_version` only when deliberately querying a different contract.
Neither tool downloads media or runs video analysis.

## Backfill existing Reels

Newly discovered Reels receive a `reel-retrieval/v1` job during dashboard sync.
To add the current stored Reel inventory, run this once from the dashboard after
the bot deployment and Atlas index are ready:

```bash
pnpm retrieval:backfill
```

It only inserts missing jobs for the active retrieval schema/version; it does
not overwrite existing enrichment jobs or trigger a run itself. The normal
one-job enrichment worker performs the model calls and vector indexing.
